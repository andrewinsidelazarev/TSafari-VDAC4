# TSafari VDAC4

Веб-браузер для ZX Evolution с платой VDAC4. Страницу загружает и раскладывает ESP32-S3 платы,
а показывает видеочип FT812, которого изображает ПЛИС Tang Nano 20K (режим Slot1): кадр
1024×768. Программа для Z80 запускает браузер и служит ему клавиатурой, мышью и картой SD.

## Что умеет

- Страницы по HTTP и HTTPS: текст, заголовки, абзацы, списки, цитаты, `pre`, таблицы, ссылки;
  после переадресации (google.com → www.google.com) адрес страницы — тот, откуда она пришла.
- CSS: `<style>`, `style=""` и внешние таблицы (`<link rel="stylesheet">`, `@import`); селекторы
  с несколькими классами, атрибутами, потомками и `>`, вес селекторов и `!important`; `@media`
  (экран 1024 × 768) и `@supports`; переменные `var(--x)`, `calc()`, все цвета CSS; текст (цвет,
  размер, жирность, регистр букв, отступ, маркеры списков); коробки (`margin`, `padding`, рамки
  по сторонам, скругление, `box-sizing`, ширины и высоты с min/max, `aspect-ratio`); колонки
  `display: flex` и `grid`; таблицы по CSS (поля и рамки ячеек, `border-collapse`); обтекание
  `float` и `clear`; `position: relative` и `absolute` (с `top`/`left`/`right`/`bottom` и
  `transform: translate()`); таблицы из блоков (`display: table`, `table-row`, `table-cell`);
  фон-картинки (`background-image`, `background-size`, `background-position`) — в блоках без
  текста (миниатюры, баннеры); скрытое (`display: none` и приёмы «только для читалок экрана»).
  Что есть и чего нет — таблица в `docs/ARCHITECTURE.md`.
- Формы: поля ввода (с флагом раскладки EN/RU), пароль, флажки, переключатели, списки,
  многострочные поля, кнопки; отправка GET и POST по HTTP и HTTPS (поиск vtrd.in).
- Картинки: JPEG (и прогрессивный), PNG всех видов и WebP разбирает BL616 платы Tang, сразу
  уменьшая до места на странице; большие WebP (и с прозрачностью 2560×2560), GIF (первый кадр),
  SVG и значки ICO (значки сайтов в выдаче DuckDuckGo) — ESP32-S3. У `<img align=left>` —
  обтекание, как у браузеров. Пока картинка грузится или если она недоступна — заглушка. Память видеочипа
  под картинки — кэш вокруг видимой части страницы: далёкие картинки убираются и при прокрутке
  обратно раскладываются снова без сети.
- Кэш картинок на карте Evo — папка `Cache\Images` рядом с `TSAFARI.SPG`, до 100 МБ: картинка
  из сети остаётся там и в следующий раз (и когда её надо загрузить снова) берётся с карты; WebP
  лежит готовыми точками экрана — с карты сразу на экран, без разбора; при переполнении удаляются
  самые старые по времени файлы. F5 («обновить») берёт картинки из сети и записывает заново.
- Таблицы стилей тоже в кэше: в памяти ESP на время работы браузера (до 512 КБ — переход по
  страницам сайта их не качает заново) и на карте в `Cache\CSS` (то же кольцо 100 МБ) — для
  следующих запусков. Порядок: память, карта, сеть; F5 — из сети и в кэш заново.
- Кодировки UTF-8, Windows-1251, KOI8-R, CP866, Windows-1252; кириллица, латиница, греческий
  и надстрочные знаки — шрифтом Noto Sans Mono, сглаженным.
- Фреймы (`<frameset>`, как у vtrd.in): фреймы идут сверху вниз, ссылка с `target` загружает
  страницу только в свой фрейм.
- Строка адреса (выезжает из-под глобуса в левом верхнем углу), поиск DuckDuckGo, история
  назад и вперёд, кнопки в горячем углу, полоса прокрутки, курсор мыши.
- Скачивание файлов (архивы, образы дисков и всё, что не страница) на карту Evo в
  `\zifi\downloads\ГГГГ-ММ-ДД\`, как у ZiFi SPG, потоком — без предела размера; ход — на
  плашке внизу слева.
- Окно подключения к Wi-Fi на старте.

- JavaScript — сам, без внешних служб: движок QuickJS и своё дерево DOM. Страница показывается
  сразу, потом выполняются её скрипты, и она раскладывается заново с тем, что они сделали (jQuery,
  меню, ленивые картинки, `document.write`, переход на другой адрес). Скрипты на ESP32-S3 идут
  примерно в 90 раз медленнее, чем на ПК: тяжёлым сайтам — секунды. Сеть из скриптов (`fetch`)
  пока не работает; большие приложения на JS (вроде zxart.ee) не помещаются в память, проверку
  поиска Google ESP считает минуты.

Пока нет: фон-картинок под текстом и их повтора, лент-каруселей с прокруткой вбок (`overflow` и
`transform` у дорожки слайдов). Страница — до 2 МБ.

## Что нужно

- ZX Evolution с платой VDAC4: Tang Nano 20K с ядром FT812 в слоте 1, ESP32-S3 с прошивкой
  VDAC4 **0.1.122** или новее (с 0.1.122 прошивка даёт модулям функции математики и времени —
  без них TSAFARI.ELF с JavaScript не загрузится; с 0.1.117 — POST по HTTPS, с 0.1.119 — адрес
  после переадресации, с 0.1.121 — кэш картинок с карты порциями DMA по 8 КБ), Wi-Fi настроен
  (`zifi.ini`).
- Прошивка BL616 39 — для прогрессивных JPEG, PNG всех видов и уменьшения картинок (с 40 — и
  WebP на BL616); со старой BL616 картинки — как у FT812 (JPEG baseline и PNG 8 бит в полный
  размер).
- Мышь PS/2 и клавиатура PS/2 у Evo.

## Установка

Скопировать на карту Evo в папку `\zifi\tsafari\` три файла из `dist/TSAFARI/`:
`TSAFARI.SPG`, `TSAFARI.ELF`, `TSAFARI.FNT`. Запускать `TSAFARI.SPG` из Wild Commander.
При первом запуске программа ищет свою папку по всей карте (окно «Looking for TSAFARI.ELF…»),
дальше путь хранится в ESP.

## Управление

| Клавиша | Действие |
|---|---|
| Win | строка адреса (Enter — перейти, Esc — закрыть, Ctrl+Shift — русская/латинская раскладка) |
| мышь в левом верхнем углу | кнопки назад, вперёд, стоп, обновить |
| колесо, стрелки, PgUp/PgDn, пробел, Home/End | прокрутка |
| Ctrl+← / Ctrl+→, Alt+← / Alt+→, Backspace | назад / вперёд (Backspace — только назад) |
| F5 | обновить |
| Esc | остановить загрузку или отменить скачивание |
| F12 | выход |

## Сборка

`tools/build.ps1` (PowerShell) собирает всё в `dist/TSAFARI/`: ELF (ESP-IDF 6.0, цель
`elf` загрузчика модулей VDAC4), программу Z80 (sjasmplus, драйвер FAT32), пакет шрифтов
и SPG. Пути к инструментам (ESP-IDF, sjasmplus, Python с Pillow, исходники VDAC4) — в начале
скрипта, их нужно поправить под свой ПК. `-SkipFonts` — не пересобирать пакет шрифтов.

Проверки:
- `tests/run_host.sh` — код ELF на ПК с поддельным ядром ESP: сценарий от окна Wi-Fi до
  скачивания файла (и страница «алфавит CSS» `tests/pages/css.html`), кадры рисует модель ядра
  FT812 (стенд RTL из репозитория VDAC4);
- `tests/test_launcher.py` — программа Z80 на модели: настоящий код и драйвер FAT32, модель
  карты SD и ответы ESP (запуск, окно, загрузка файлов на карту).

Устройство браузера — `docs/ARCHITECTURE.md`; комментарии в исходниках написаны для
начинающего программиста.

## Состав

| Папка | Что там |
|---|---|
| `main/` | браузер на ESP32-S3 (C) |
| `launcher/` | программа Z80 (ассемблер sjasmplus) |
| `design/` | дизайн интерфейса (Codex): превью, `ui_design.h`, ресурсы FT812 |
| `tools/`, `tests/` | сборка и проверки |
| `fonts/noto/` | шрифты Noto для пакета письменностей мира |
| `third_party/` | драйвер FAT32 для ZX Evolution, miniz (распаковка zlib), libwebp (разбор WebP), nanosvg (SVG) |
| `dist/TSAFARI/` | готовые файлы для карты |
