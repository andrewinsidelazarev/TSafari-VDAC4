# Ресурсы FT812 — этап 3

Сборка: `..\build_ft_assets.cmd`. Манифест — [assets.json](assets.json); C-константы — [ui_design.h](../ui_design.h). Имена исходных PNG сохранены. Дополнительный `js_label.png` — надпись «JS» из того же Noto Sans Mono 20 px, ячейка 12×34, baseline 26; внешний вид метки не меняется.

## Загрузка

Статический пакет: **ui_assets.bin**, **18 712 байт**. В пакете иконки, лента глобуса, курсор, надпись JS, готовый заголовок wifi_title и метки input_en/input_ru. Первые 18 008 байт совпадают с предыдущей версией; метки добавлены только в конец файла. Пакет не содержит дисплей-листа, страницы, палитр или динамического текста. Это файл для интеграции; запись в устройство не выполнялась.

**Теперь загрузка по двум диапазонам, манифест version=3:**

| file_offset | bytes | ram_g |
|---:|---:|---|
| 0 | 18 008 | 0x0E1000 |
| 18 008 | 704 | 0x0EDB70 |

Использовать `load_plan`: прочитать `bytes` байт с `file_offset`, записать по `ram_g`. Константы — `TSA_UI_BUNDLE_SEGMENT_*`. Поле `bundle.ram_g` заменено `bundle.segmented=true`: **не записывать весь файл подряд с 0x0E1000**, иначе хвост попадёт в старый буфер подсказки. Такое размещение сохраняет все прежние адреса ресурсов, буферов и резерва, без пустого дополнения файла.

**Этап 3 сохраняет весь файл и оба диапазона без изменений.** Для плашки используются прежние download/check/warning/close; курсор перекрашивается COLOR_RGB. Новых статических ресурсов и третьего диапазона загрузки нет. В манифест добавлен только динамический буфер `download_text`, который заполняет ESP.

В `assets.json`:

- `file` — отдельный файл относительно `ft/`; `png` — исходник относительно той же папки.
- `format`, `format_code`, `width`, `height`, `stride`, `bytes` — параметры хранения; stride всегда в байтах.
- `bundle_offset` — смещение внутри `ui_assets.bin`; `ram_g` — абсолютный адрес ресурса после загрузки соответствующего диапазона. Для нового хвоста `ram_g` не равен 0x0E1000 + bundle_offset.
- `canonical=true` — самостоятельная область памяти. `globe_00`…`globe_11` имеют `canonical=false`: они ссылаются на ячейки `globe_strip`, не увеличивая RAM_G.
- `load_plan` содержит две загрузки из одного пакета. Отдельные файлы нужны, если загрузчик предпочитает ресурсы по одному; одновременно загружать пакет и копии кадров не требуется.
- `buffers` описывает маски, которые создаёт ESP. Они не имеют статических файлов; перед использованием их нужно очистить.
- `startup_views` — три альтернативных представления этих же буферов для модального окна Wi-Fi. `alias_of_buffers` перечисляет соседние буферы, используемые маской. Они не увеличивают расход RAM_G и не могут выводиться одновременно с обычными подсказками/статусом. После смены режима содержимое необходимо перерисовать. Статический wifi_title сюда не входит и при смене режима не очищается.

Все ресурсы и размеры пакета кратны четырём байтам. Выравнивание строк сверх указанного stride отсутствует. Упаковка идёт сверху вниз, слева направо, без транспонирования и без сжатия.

## Форматы

**L4 / код 2:** 16 иконок, глобус, надпись JS, заголовок wifi_title и метки input_en/input_ru. Старшая тетрада байта — alpha левого/чётного пикселя; младшая — следующего. PNG-маски уже содержат 16 уровней альфы, поэтому преобразование сохраняет её точно. Белые RGB-каналы не записываются. Цвет задаётся COLOR_RGB, общая прозрачность — COLOR_A, без premultiply. Семантика маски сверена с локальным `ft_rd_exec.sv`: для L4 RGB=255, alpha берётся из тетрады.

**ARGB4 / код 6:** только курсор Zuma. Каждый пиксель — 16-битное слово **A4R4G4B4, little-endian**. Все каналы усечены `channel >> 4`, точно как в исходном `make_cursor.py`. PNG курсора остаётся исходным, без дополнительного квантования; бинарник совпадает с полезными 2888 байтами оригинального FT812-курсора. На обычной/посещённой ссылке использовать **COLOR_RGB=0x73DFC6**, в остальных местах **0xFFFFFF**; COLOR_A=255. Острие (1,1), bitmap-вершина = положение мыши минус (1,1). `TSA_UI_CURSOR_LINK_*` ссылается на тот же ресурс. Alpha не меняется, RGB умножается поканально с делением на 255.

ARGB1555 не используется: одна битовая альфа потеряла бы сглаживание. Маскам достаточно L4, а курсору нужен цвет и четырёхбитная альфа.

## Глобус и большие текстовые маски

`globe_strip.l4`: ширина 32, высота хранения 384, stride 16, 6144 байта. Для анимации выставлять **BITMAP_LAYOUT height=32**, BITMAP_SIZE 32×32 и CELL=0…11. Шаг ячейки 512 байт, период кадра 100 мс. Если используется отдельный `globe_NN.l4`, источник равен его `ram_g`, а CELL=0.

Адрес: **648×34 L4**, stride 324, **0x0F0000**, 11 016 байт; 54 видимые ячейки по 12 px. Перерисовываются только данные маски. Выделение и каретка рисуются примитивами, а не запекаются в текст.

Подсказки: три буфера **320×34**, stride 160, по 5440 байт. Статус ссылки: **984×34**, stride 492, 16 728 байт. Их адреса находятся в манифесте и в макросах `TSA_UI_BUFFER_*`. Надпись JS — готовый `js_label.l4`, 24×34, stride 12, 408 байт; координаты (946,718).

Для адреса и статуса ширина больше 511: нужны корректные старшие биты BITMAP_SIZE_H. Перед выводом UI восстановить обычное преобразование битмапа и ожидаемый режим смешивания. Больших полупрозрачных текстур нет; фоны и круги рисуются примитивами.

Стартовое окно Wi-Fi использует прежние globe/warning. **wifi_title.l4** — готовый TSafari 32 px: **144×55, stride 72, 3960 байт, RAM_G 0x0E46E0**, смещение в пакете 14048. Выводить по **(440,226)** цветом `TSA_UI_WIFI_TITLE_RGB888`, COLOR_A=255. Параметры ресурса — `TSA_UI_ASSET_WIFI_TITLE_*`, координаты — `TSA_UI_WIFI_TITLE_X/Y`. Шрифт 32 px в ELF не нужен; смещение текста x=5 уже запечено в PNG.

Подпись `Web browser for VDAC4 ZX Evolution` рисуется имеющимся атласом **20 px**, 34 ячейки по 12 px, по **(308,284)**. Маска subtitle — **408×34, stride 204, 6936 байт**, занимает начало объединённых suggestion_0 + suggestion_1. State 320×34 использует suggestion_2, hint 480×68 — status_text. Их параметры — `TSA_UI_WIFI_BUFFER_*`. Заголовок title теперь статический; все адреса версии с wifi_title сохранены при добавлении EN/RU. Подключать соответствующие версии манифеста и заголовка вместе. Рисование и переходы описаны в [DESIGN.md](../DESIGN.md).

## Метки языка ввода

`input_en.l4` и `input_ru.l4`: **32×22, stride 16, 352 байта каждая**. EN: RAM_G **0x0EDB70**, смещение в файле **18008**. RU: RAM_G **0x0EDCD0**, смещение **18360**. Цвет — `TSA_UI_INPUT_LANG_RGB888`, COLOR_A=255, фон прозрачный. Рамка и текст — единая маска; атлас 16 px в коде не требуется.

Вывод по **(caret_x+6,17)**: от правого края каретки до метки 4 px. Показ только в конце текста, без выделения, с фокусом адресного поля и после окончания выезда. Ctrl+Shift переключает EN/RU; при мигании каретки метка остаётся. Для длинного адреса ограничить экранный caret_x значением 892 через прокрутку текста; край метки 930 оставляет 8 px до Go. После рисования текста расширить SCISSOR для индикатора до `TSA_UI_INPUT_LANG_CLIP_*`.

## Константы и движение

Текст фонового скачивания: **480×68 L4, stride 240, 16 320 байт**, `TSA_UI_DOWNLOAD_RAM_G_BASE=0x0F4000`, конец **0x0F7FC0**, в разрешённом окне остаётся 64 байта. Этот буфер **не входит в пакет**; очистить до первого вывода и заполнить из атласа 20 px (ячейка 12×34, baseline 26). В первой строке отступ 36 px под значок и до 34 ячеек текста, во второй — от x=0 до 40 ячеек. Выводить **одним** битмапом в (24,y+4), где y=656 либо 608 при строке состояния ссылки. Для ширины 480 старшие биты BITMAP_SIZE_H должны быть нулевыми после более широких масок.

Плашка — RECTS/POINTS и существующие иконки. Геометрия/цвета/времена — `TSA_UI_DOWNLOAD_*`. Готово скрывается через 5000 мс, ошибка — 8000, отмена — 3000; наведение приостанавливает отсчёт. Неопределённая полоса: ширина 96, ход 384, период 1400 мс. Поведение отмены и длинных имён — [DESIGN.md](../DESIGN.md). Общий расчёт DL — 250 слов с резервом 24; аппаратный DL в этой работе не запускался.

`ui_design.h` содержит RGB888 и RGB565, геометрию, задержки, прозрачности, адреса ресурсов и масок. `TSA_UI_ASSET_GLOBE_STRIP_HEIGHT=384` — размер хранения; для bitmap-ячейки использовать `TSA_UI_ASSET_GLOBE_STRIP_CELL_HEIGHT=32`.

Линейные таблицы индексируются целыми миллисекундами, с ограничением индекса до длительности. Для выезда: `NAV_X−tsa_ui_nav_offset_px[t]`, глобус: `GLOBE_OPEN_CENTER_X−tsa_ui_nav_offset_px[t]`; адрес: `ADDRESS_X+tsa_ui_address_offset_px[t]`. При обратном ходе индекс `duration−elapsed`. Альфа глобуса — `tsa_ui_nav_globe_alpha[t]`; наведение в покое использует 220. Никаких float и функций в заголовке нет.

Кольцо PALETTED565 и палитры остаются в ведении кода страницы. Ресурсы не вносят изменений в `main`.
